# LeafyAI FULL Integration Fix Notes — 2026-09-12

This revision fixes the startup failures observed in Docker logs:

- Camera and LeafyCV no longer restart-crash on one transient Backend/auth error.
- Compose supplies a local-only bootstrap service account by default so `docker compose up --build` works without manually provisioning JWTs.
- `seed_base` synchronizes the bootstrap password on reused Docker volumes and reports the real Camera count.
- `.env` is optional for safe local startup. Lab/shared deployments should override all local defaults in `.env`.
- Camera + LeafyCV start by default. With zero Camera rows they remain idle and make no RTSP/WEBCAM connection.
- Sensors start safely with blank hardware URLs and wait in a not-configured state instead of issuing invalid URL requests.
- Powerboard starts safely with blank board IPs and returns `NOT CONFIGURED` instead of hardware `ERROR` without attempting Kasa discovery.
- No Camera IP is hard-coded. A physical camera is contacted only after it is added in Plant Vision.
- No `runtime/` folder is shipped; Docker uses named volumes.

## Fresh zero-camera test

```powershell
docker compose down -v
docker compose up --build
```

Expected:

- Backend healthy
- Frontend available at http://localhost:5173
- Camera service running, zero cameras, no RTSP connection
- LeafyCV running, zero cameras/images to analyse
- Sensor worker idle if hardware URLs are blank
- Powerboard reports Not configured if board IPs are blank

When you add a Camera in Plant Vision, the Camera worker should detect it on the next poll without restarting the service.
