# LeafyCV1.0 -> Current Django Backend Contract

This contract matches the `computer_vision/models.py` supplied by the team.

## What is confirmed

### ImageAnalysis
LeafyCV sends:
- `total_canopy_coverage`
- `visible_plant_count`
- `measurement_valid`
- `processing_time_ms`

The backend supplies the `image` OneToOne relationship to `CameraImage`.
`created_at` is generated by Django.

### PlantVisionMeasurement
LeafyCV sends exactly:
- `slot_id` (integer: 1, 2, 3, ...)
- `canopy_coverage`
- `width_px`
- `height_px`
- `width_cm`
- `height_cm`
- `green_percentage`
- `yellow_percentage`
- `crowding_percentage`
- `growth_change`
- `visible`
- `measurement_valid`

The backend supplies `analysis` and Django supplies `created_at`.

## Payload

Recommended POST body is multipart/form-data:

- `metadata`: JSON string
- `raw_image`: original camera JPEG

Example metadata:

```json
{
  "model_version": "LeafyCV1.0",
  "camera_name": "level1_camera2",
  "captured_at": "2026-08-09T18:00:00+10:00",
  "size_calibrated": false,
  "analysis": {
    "total_canopy_coverage": 48.22,
    "visible_plant_count": 4,
    "measurement_valid": true,
    "processing_time_ms": 181
  },
  "plants": [
    {
      "slot_id": 1,
      "canopy_coverage": 41.50,
      "width_px": 302.0,
      "height_px": 268.0,
      "width_cm": 0.0,
      "height_cm": 0.0,
      "green_percentage": 88.10,
      "yellow_percentage": 8.30,
      "crowding_percentage": 50.0,
      "growth_change": 1.75,
      "visible": true,
      "measurement_valid": true
    }
  ]
}
```

## Definitions

### slot_id
The actual Django model uses `models.IntegerField()`, so LeafyCV sends the
registered physical slot order directly:

- first registered centre -> `slot_id = 1`
- second registered centre -> `slot_id = 2`
- etc.

There is no UUID mapping in this version.

### growth_change
`growth_change` is the change in smoothed slot canopy coverage since the
previous saved CV sample, measured in percentage points.

Example:
- previous canopy = 40.00
- current canopy = 42.50
- growth_change = 2.50

The first sample after LeafyCV starts (or after slots are re-registered) uses
`growth_change = 0.0`.

### crowding_percentage
Percentage of that slot's neighbouring slot interfaces currently in visual
canopy contact.

### width_cm / height_cm
The current backend defines these as non-null FloatFields. Therefore:
- calibrated -> actual estimated cm
- not calibrated -> `0.0`

`size_calibrated` is also sent at metadata level so the backend/front end
should not interpret `0.0` as a real physical size.

A future backend improvement could make these fields nullable.
